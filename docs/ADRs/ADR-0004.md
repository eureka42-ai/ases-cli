# ADR-0004 — Scheduler, leases com fencing, Git worktrees e fila de merge

- **Status:** ACCEPTED (PHASE-05, 22/11/2026)
- **Tarefas:** TAR-0021..TAR-0026
- **Requisitos:** AER-REQ-037, 041..047, 050..060, 158, 164, 186, 189

## Decisão
1. **Primitivas transacionais no `ProjectStore`** (migração 2), com o **scheduler puro por cima** (`@aer/scheduler`).
   - Reserva com verificação de estado, dependências, lease vivo, capacidade global/por provider e recurso compartilhado, tudo **dentro da mesma transação `BEGIN IMMEDIATE`**. Por isso os limites valem entre processos.
   - Fencing token monotônico por tarefa (`tasks.fencing_seq`). Transições do executor só com token vivo (`transitionTaskFenced`). Token antigo ou lease vencido → `STALE_LEASE`.
   - Lease vencido: `RESERVED` volta a `READY` (nada começou); `RUNNING`/`VERIFYING` vai para `BLOCKED` com motivo `LEASE_EXPIRED`, e o attempt fica `UNKNOWN`. **Nada é reiniciado sozinho** (§5.3-7).
2. **Ordem do scheduler:** prioridade ↓, quantas tarefas desbloqueia (transitivo) ↓, ID ↑. A explicação (critérios + alternativas) vai no evento `TaskReserved` (AER-REQ-050). `/schedule` mostra a ordem sem reservar.
3. **DAG:** dependências podem ser adicionadas depois da criação; ciclo recusado com o caminho (`cycle: A -> C -> B -> A`).
4. **`@aer/git-bridge`** sobre o Git oficial, `execFile` sem shell e `GIT_TERMINAL_PROMPT=0`.
   - Worktree `.ases/worktrees/TAR-XXXX-ATT-XXXX`, branch `ases/TAR-XXXX/ATT-XXXX` e base commit registrado no attempt.
   - `resolveInside` recusa `..`, caminho absoluto, symlink de diretório e **symlink quebrado** apontando para fora (defeito real encontrado no teste).
5. **Fila de merge:**
   - Trava `merge:<alvo>` no banco (um merge por vez, entre processos). Pré-condições (estar no alvo, checkout limpo) checadas **antes** de `MERGING`.
   - `git merge --no-ff`; conflito → `merge --abort` (seguro porque a árvore estava limpa) e `CONFLICT`.
   - Nunca `reset --hard`, `clean` ou `--force`. Merge sem evidência fica em `MERGING`, nunca falso `COMPLETED`.
6. **Gate de evidência no banco:** `COMPLETED` exige artefato (caminho relativo + SHA-256) ou test run, e o último test run não pode estar falhando (`EVIDENCE_REQUIRED`/`TESTS_FAILING`).
7. **Corte do `.ases/` interino** (`ases migrate-interim`):
   - importação transacional preservando `eventId`, `seq`, horários e hash, só em banco vazio;
   - backup do espelho; verificação de que o novo `HISTORY.jsonl` começa byte a byte com o antigo;
   - a partir daí o `scripts/ases-dev.mjs` só faz `verify`.
8. **Banco ausente com histórico do engine** (clone novo, outra worktree): `DB_MISSING`. O engine recusa iniciar, porque criaria banco novo e sobrescreveria o histórico versionado. Restauração a partir do espelho: Project Passport (PHASE-11).

## Consequências
- O engine (escritor único) roda no checkout principal. Worktrees de fase/tarefa não carregam o banco, por desenho.
- A execução de agentes dentro das worktrees chega na PHASE-06 (simulador). Aqui o ciclo é exercitado por testes com Git real.
