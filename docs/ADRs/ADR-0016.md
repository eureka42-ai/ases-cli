# ADR-0016: Continuidade entre providers, test runs reais, revisão independente, recovery e usage

- **Status:** PROPOSED (PHASE-11, 23/11/2026). Aguarda revisão humana.
- **Tarefas:** TAR-0054..TAR-0058
- **Requisitos:** AER-REQ-150, 176..189

## Decisão
1. **Continuidade:**
   - Toda nova tentativa de uma tarefa parte da **ponta da branch da tentativa anterior** (`nextAttemptBase`), e não do HEAD do projeto. A cadeia de checkpoints preserva os arquivos de todos os providers.
   - O merge já usa a última branch, que contém tudo.
2. **`/handoff TAR <provider> <motivo>`:**
   - só para tarefa parada (REVIEW, REWORK, FAILED ou BLOCKED, sem lease);
   - sobras não commitadas da tentativa anterior viram um **checkpoint de recuperação NÃO verificado**;
   - troca o provider e grava `.ases/handoffs/TAR-…-Hnn.md`, como artefato e evento `HandoffCreated`.
   - **Conteúdo do HANDOFF:** motivo, último evento confirmado, estado Git (branch/ponta/checkpoints), diff da última tentativa e o acumulado, test runs reais (ou "validação NÃO concluída") e a próxima ação segura.
   - Ele declara "resumo ≠ fonte", com ponteiros para os seq de evento e os commits (AER-REQ-176/178/184).
3. **Pacote de contexto do agente** (AER-REQ-177/179): só a tarefa, os requisitos dela (título e aceite, quando a matriz existe) e o último handoff, dentro de um orçamento de 16 000 caracteres.
   - Se o handoff não couber, ele é truncado com um ponteiro para o arquivo completo.
   - O handoff é marcado como **dado, não instrução**.
4. **`/test TAR <comando>`** (AER-REQ-186/188/189):
   - roda o comando **sem shell** numa worktree temporária do último checkpoint;
   - exige aprovação `EXEC_TESTS` do argv exato, de uso único (policy engine da PHASE-10);
   - grava o test run com exit e horários, mais o log redigido como evidência.
   - As contagens não são inventadas: o exit code é a verdade (total/passed = 0 quando o runner não é interpretado).
5. **`/review TAR <provider>`** (AER-REQ-187):
   - um provider que **não escreveu nenhuma tentativa** da tarefa revisa o último checkpoint em modo `READ_ONLY`, numa worktree própria;
   - qualquer alteração no disco torna a revisão `INVALID (REVIEWER_WROTE)`, e as alterações são descartadas;
   - o parecer (APPROVED/REJECTED/UNCLEAR) vira relatório; **o estado da tarefa não muda**, porque a decisão é humana.
6. **`/resume`** (AER-REQ-180/182): expira leases vencidos e, para tarefas BLOCKED por `LEASE_EXPIRED/LEASE_LOST/WORKER_ERROR`, salva as sobras como checkpoint de recuperação e volta a tarefa para READY. **Não cria tentativas** e é idempotente.
7. **`/usage [TAR]`** (§8, AER-REQ-150): soma por provider e métrica, com a fonte.
   - Providers diferentes **nunca** são somados.
   - Provider sem dado aparece como `—`, não como zero.

## Consequências e limites
- **Escopo da continuidade:** ela segue a cadeia da última tentativa. Recomeçar do main exigiria uma nova tarefa; não há flag `--fresh`.
- **Pedido de permissão do agente em tempo real:** continua negado pela política fixa; `/approval` cobre extensões e test runs.
- **Contagem de testes:** não é interpretada (nenhum parser de runner).
- **Gate e2e com dois providers:** o e2e (`test/e2e/continuity.test.mjs`) usa o falso `claude`, um script sh, e por isso roda só em POSIX. No Windows, a troca de provider é coberta pelo teste de unidade do scheduler (simulador sob dois ids).
