# ADR-0003 — IPC local (UDS / Named Pipe), autenticação, engine embutido e CLI sem framework

- **Status:** ACCEPTED (PHASE-03, 22/11/2026)
- **Tarefas:** TAR-0011..TAR-0015
- **Requisitos:** AER-REQ-014, 071–080, 090, 091, 170, 227, 228

## Decisão

1. **Transporte:** `node:net` sobre o caminho de `PlatformAdapter.createLocalIpcEndpoint()`.
   - macOS/Linux: Unix Domain Socket `<runtimeDir>/engine.sock`, com o diretório em `0700` (dono verificado, symlink recusado) e o socket em `0600`.
   - Windows: Named Pipe `\\.\pipe\ases-{userHash}-{projectHash}`.
   - Nenhuma porta TCP.
2. **Protocolo:** JSON-RPC 2.0, uma mensagem por linha (NDJSON).
   - Frame limitado a 1 MiB; o excesso fecha a conexão.
   - Handshake obrigatório em até 5 s: versão de protocolo, `projectId`, papel e token.
   - Timeout por chamada no cliente.
3. **Autenticação por token de sessão:** a cada início, o engine gera dois tokens aleatórios de 256 bits, `control` e `monitor`, e os grava em `<runtimeDir>/session.json`, escrito de forma atômica em `0600`. Só quem lê esse arquivo (o mesmo usuário) consegue conectar. Os métodos mutantes exigem o papel `control`, e o servidor recusa o token de monitor com `FORBIDDEN` (C20). O `ases-tar` só usa o token de monitor.
4. **Engine embutido no `ases`** (permitido pelo §3.4 para a primeira fatia vertical).
   - O `listen()` do endpoint funciona como **lock de escritor único**: um segundo `ases` recebe `ENGINE_ALREADY_RUNNING` antes de abrir o banco como escritor.
   - Socket órfão de um engine morto é detectado (a conexão falha) e substituído.
   - Fechar o `ases` encerra o engine e avisa isso explicitamente. **Não há continuidade após fechar a UI**; o supervisor é a PHASE-12.
5. **Assinatura sem corrida:** `project.subscribe({fromSeq})` envia o backlog e passa para "ao vivo" no mesmo tique síncrono do processo do engine (single-thread, escritor único). Um assinante lento acima de 4 MiB em buffer perde a assinatura e recebe `project.resyncRequired`; o engine nunca bloqueia. O cliente descarta `seq` repetido e, se houver lacuna, reconecta a partir do último `seq` confirmado.
6. **CLI com `node:util.parseArgs`** em vez do Commander citado no §3.1. Hoje são poucos subcomandos e isso evita uma dependência nova. Reavaliar quando houver subcomandos aninhados.
7. **Build:** `tsc -b` com project references (`tsconfig.build.json` por pacote), `rewriteRelativeImportExtensions`. Os bins `apps/*/bin/*.js` importam `dist/`. O pacote npm único com dois bins fica para a PHASE-12.

## Riscos residuais

- **Windows:** o Named Pipe usa a DACL padrão do sistema, e a ACL do diretório de runtime (`%LOCALAPPDATA%`) não é verificada (`ensurePrivateDir` é *shortcut* no Windows). O token em arquivo do perfil do usuário é a barreira efetiva. **`SECURITY_CONTROL_INCOMPLETE` no Windows até a PHASE-15** (AER-REQ-227).
- Não há verificação de credencial do peer (`SO_PEERCRED`/`getpeereid`); em POSIX a proteção vem do diretório `0700`, do socket `0600` e do token.
- O espelho `HISTORY.jsonl` é reescrito por completo a cada mutação (*shortcut*, O(n)).
- O `.ases/` do próprio AER continua interino; o engine se recusa a abri-lo (`INTERIM_PROJECT`) para não virar segundo escritor.
