# ADR-0017: Motor residente sem supervisor do SO; pacote npm único e autocontido

- **Status:** PROPOSED (PHASE-12, 23/11/2026). Aguarda revisão humana.
- **Tarefas:** TAR-0059..TAR-0062
- **Requisitos:** AER-REQ-004, 231, 232, 233, 235

## Decisão
1. **Motor residente** (`ases daemon start|stop|status`):
   - O engine roda num processo **destacado** (`detached`, sem console no Windows), com stdout/stderr num log privado no diretório de runtime (`0700`).
   - O endpoint IPC continua sendo o lock de escritor único.
   - **Cliente:** o `ases` interativo, quando encontra um motor residente vivo, vira **cliente `control`**. Cada linha vai pelo método IPC `session.command`, que exige o token de controle do arquivo de sessão privado.
     - `/exit` só desliga o cliente.
     - `/shutdown` ou `ases daemon stop` param o motor, cancelando as tarefas com a árvore de processos.
   - **`/run` no motor:** retorna na hora e segue no motor. O resultado vai para o log e para os eventos; `ases-tar` e `/tasks` acompanham.
   - **Motor que não é residente:** se o motor for outro `ases` interativo (sem `commandHandler`), o cliente recusa com `ENGINE_ALREADY_RUNNING`, como antes.
2. **Supervisor do SO** (launchd, systemd --user, Agendador/Serviço no Windows): **não habilitado** nesta fase. `daemon status` mostra `supervisor: NONE`.
   - **O que isso implica:**
     - fechar a TUI ou o terminal **não** perde tarefas;
     - reboot, logoff ou crash do motor **não** são cobertos; a recuperação é o `/resume` da PHASE-11;
     - nada exige admin (AER-REQ-235).
   - Gerar e instalar unidades do SO mexeria em arquivos do usuário fora do projeto (`~/Library/LaunchAgents`, `~/.config/systemd/user`). Isso fica para quando houver decisão explícita e um teste por SO.
3. **Pacote npm único** (`scripts/pack.mjs`):
   - **Conteúdo:** `@eureka42-ai/aer`, com os bins `ases` e `ases-tar`, **autocontido**. Embute os 21 pacotes `@aer/*` compilados e o fecho transitivo de zod, ink e react (41 pacotes de terceiros, nas versões do lockfile, cada um com a própria licença).
   - Instala com `--offline`. Leva as fontes ASES e o `LICENSE`. Nada é publicado no registro npm.
4. **Smoke do pacote** (`scripts/pack-smoke.mjs`, no CI de cada SO):
   - instala num prefixo temporário (o npm global do usuário não é tocado);
   - roda os comandos **pelo PATH** em cada shell presente (bash/zsh/pwsh; no Windows, pwsh, Windows PowerShell e cmd);
   - faz `init` + `/ases import` + `/gate G0`;
   - desinstala e confere que os atalhos somem e os dados do projeto ficam.

## Consequências e limites
- O cliente ligado ao motor residente é **modo linha**. A TUI Ink continua só no `ases` que sobe o próprio engine; uma TUI cliente do motor residente fica para depois.
- **Atualização e rollback:** reinstalar o `.tgz`. As migrações do banco fazem backup antes, e uma versão antiga recusa banco mais novo (`DB_SCHEMA_TOO_NEW`). Ver `docs/INSTALL.md`.
