# ADR-0012 — Contrato de provider, simulador determinístico e ciclo de vida do worker

- **Status:** PROPOSED (PHASE-06, 23/11/2026). Aguarda revisão humana.
- **Tarefas:** TAR-0027..TAR-0031
- **Requisitos:** AER-REQ-101..110, 043

## Decisão
1. **`@aer/provider-sdk`** traz o contrato §7.2 versionado (`PROVIDER_CONTRACT_VERSION = 1`) e não importa nada de SO.
   - Acréscimo ao §7.2: evento `exit` (`exitCode`, `signal`, `cancelled`, `reconciled`). Ele é **sintetizado pelo adapter** a partir do processo real. Se o agente enviar um `exit`, o evento vira `PARSE_ERROR`.
   - `ProviderProbeResult` ganhou `contractVersion` e `simulated`.
2. **Stream:** a entrada é NDJSON incremental. Os testes cobrem chunks cortados no meio do UTF-8, CRLF e um limite por linha (1 MiB, linha maior é descartada).
   - O schema é estrito (zod). Formato desconhecido vira `PARSE_ERROR`, e um `PARSE_ERROR` nunca termina em sucesso: tentativa `UNKNOWN`, tarefa `FAILED`.
3. **Simulador:** é um **processo real** (`agent/sim-agent.mjs`, Node), não uma função em memória.
   - Assim, spawn, pipes, exit code, timeout e kill de árvore são exercitados de verdade.
   - Cenários: `ok`, `fail`, `hang` (com neto), `approval`, `auth-expired`, `garbage`, `escape`. A tarefa escolhe o cenário com `--provider simulator:<cenário>`.
   - O probe só roda `--version` e aceita apenas as versões listadas (AER-REQ-102/103).
4. **Processos:** `spawnManagedProcess` usa `shell:false`.
   - POSIX: `detached` dá ao agente um grupo próprio. `terminateProcessTree` manda SIGTERM ao grupo, espera, manda SIGKILL e só confirma `terminated` quando o grupo não existe mais.
   - Windows: `taskkill /T /F`.
   - Mesmo após saída normal, o grupo é reconciliado. Árvore não confirmada leva a tarefa a `BLOCKED PROCESS_TREE_NOT_RECONCILED`.
5. **Worker (`runAttempt`):** recebe um lease, cria uma worktree por tentativa e roda o provider com heartbeat. Cada evento do stream vira evento do store:
   - `ProviderOutputChunk` (texto redigido e truncado), `ProviderToolCall/ResultObserved`, `ProviderUsageObserved`, `ApprovalRequested`, `SecurityViolationBlocked`, `GitCheckpointCreated`.
   - Todos os payloads levam `providerId` e `simulated`.
6. **Destino da tarefa** (decidido na ordem abaixo):

   | Condição | Tarefa | Tentativa |
   |---|---|---|
   | árvore não reconciliada | BLOCKED | UNKNOWN |
   | lease perdido | (não publica) | UNKNOWN |
   | fuga de caminho | FAILED | FAILED |
   | pedido de aprovação | BLOCKED `APPROVAL_REQUIRED` | CANCELLED |
   | cancelado pelo usuário | CANCEL_REQUESTED, depois CANCELLED | CANCELLED |
   | `AUTH_EXPIRED`/`RATE_LIMITED`/... | BLOCKED com o código | FAILED |
   | timeout | FAILED | FAILED |
   | `PARSE_ERROR` | FAILED | UNKNOWN |
   | exit ≠ 0 | FAILED | FAILED |
   | exit 0 limpo | VERIFYING, depois REVIEW | EXITED + commit na branch da tentativa |

   **O worker nunca aprova nem integra.** REVIEW → APPROVED é decisão humana, e o merge continua no `mergeTask` (ADR-0004).
7. **`ases`:**
   - `/run [PHASE] [--parallel N] [--timeout S]` roda `runQueue` (tick + workers até nada ser elegível). `/cancel TAR-XXXX` cancela uma tarefa.
   - Sair (`/exit`, Ctrl+C, SIGTERM) cancela e reconcilia as tarefas em execução e informa quantas foram canceladas.
   - No modo linha, os comandos rodam em fila, então um script `/run` + `/exit` espera o run terminar.
   - `/task new` aceita `--reqs`, `--provider` e `--resources`.

## Consequências / limites conhecidos
- **Aprovação:** sem canal de aprovação nesta fase, o pedido bloqueia a tarefa e encerra o agente. `/approval` chega na PHASE-10.
- **Engine morto à força (SIGKILL):** o agente fica órfão (grupo próprio). O lease expira e leva a tarefa a BLOCKED com tentativa UNKNOWN, mas o processo não é morto. O supervisor está planejado para a PHASE-12.
- **Windows:** só o pid raiz é confirmado após `taskkill`. A verificação de descendentes (Job Objects) fica para a PHASE-15.
- **stderr do agente:** é descartado. Capturar redigido quando houver providers reais (PHASE-07).
- **Redação:** a redação de segredos usa uma lista fixa de padrões. O scanner completo vem na PHASE-10.
