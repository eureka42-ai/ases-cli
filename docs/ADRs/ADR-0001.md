# ADR-0001 — Arquitetura modular, duas TUIs, engine local e monorepo npm

- **Status:** ACCEPTED (PHASE-01, 22/11/2026)
- **Tarefas:** TAR-0002, TAR-0003, TAR-0005
- **Requisitos:** AER-REQ-005, 006, 007, 010, 225, 226

## Contexto

O MD mestre (§3) define um runtime local TypeScript com dois bins (`ases`, `ases-tar`), engine compartilhado, SQLite como autoridade, IPC local (UDS/Named Pipe) e `PlatformAdapter` desde o primeiro commit. O host inicial é macOS 27.2.1 arm64, Node 22.19.0 e npm 10.9.3. O pnpm não está instalado.

## Decisão

1. **Monorepo com npm workspaces** (`packages/*`; `apps/*` entra na PHASE-03), em vez do pnpm sugerido no §3.2. Decisão CONFIRMED pelo responsável em 22/11/2026. Motivo: o npm já vem com o Node nos três SO, nada global precisa ser instalado e o `npm pack` é o mesmo canal de distribuição.
2. **TypeScript 6.0.3 strict** com `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` e `verbatimModuleSyntax`, `module: NodeNext`. Os pacotes exportam `src/*.ts` pela condição `source` (usada pelo `tsc` e pelo vitest) e `dist/*.js` como `default`. Ainda não há build: ele chega na PHASE-03, junto com os bins.
3. **Pacotes da PHASE-01:** `contracts` (IDs, versões, estados, schema do manifest, sem nenhuma dependência interna), `platform-core` (contrato `PlatformAdapter` e funções puras parametrizadas por SO) e `platform-macos`, `platform-windows`, `platform-linux` (fábricas de adapter). Os demais pacotes do §3.2 serão criados quando a fase correspondente começar. Nada de pacote vazio "para depois".
4. **Lint de arquitetura** próprio (`scripts/check-boundaries.mjs`) no lugar do ESLint. Ele bloqueia: pacotes portáveis importando `platform-macos/windows/linux`; `contracts` importando `@aer/*`; `ink`/`react` fora de `tui-shared`/`branding`; um adapter de SO importando outro; `shell: true`; importar `exec`/`execSync`. O ESLint pode entrar depois, via ADR, se as regras de estilo justificarem.
5. **Dependências fixadas em versão exata** e publicadas há ≥ 2 semanas: typescript 6.0.3, vitest 4.1.12, vite 7.3.8, zod 4.6.7, @types/node 22.20.5. O TypeScript 7 (publicado em 21/11/2026) foi recusado por ser recente demais.
6. **`.npmrc`:** `ignore-scripts=true` (scripts de install negados por padrão, §9.6) e `legacy-peer-deps=true`. O segundo contorna o bug do npm 10.9.3 `Cannot read properties of null (reading 'edgesOut')` em `#loadPeerSet`, disparado pela cadeia de peers opcionais `vite@8 → @vitejs/devtools → vitest@*`. O `vite@7.3.8` direto evita o vite 8. Consequência: peers não são instalados automaticamente; todo peer necessário precisa ser dependência direta.
7. **Estado `.ases/` interino:** `scripts/ases-dev.mjs` (sem dependências) cria e atualiza `.ases/` de forma não destrutiva e grava `HISTORY.jsonl` com `seq` e `payloadSha256`. Isso **contraria temporariamente** o §6.1, que pede SQLite como autoridade. Na PHASE-02 o histórico é importado como seed e o JSONL passa a ser espelho derivado do banco.
8. **Engine ↔ UI:** fica como no §3.4. Na PHASE-03 o engine roda como subprocesso controlado pelo `ases`, e a supervisão residente fica para a PHASE-12.

## Diferenças em relação ao MD mestre

| MD mestre | Este repositório | Motivo |
|---|---|---|
| pnpm + `pnpm-workspace.yaml` | npm workspaces + `package-lock.json` | decisão do responsável; zero instalação global |
| ESLint implícito em "lint" | lint de fronteiras próprio | cobre as regras normativas sem 100+ dependências |
| SQLite autoridade desde o início | JSONL interino até a PHASE-02 | o bootstrap precede o engine (permitido pelo §0.1-6) |
